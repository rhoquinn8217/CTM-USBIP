## Knowledge learned (verified on-device unless noted)

- **webOS RCU Back = scancode 484, sym 0** under stock SDK SDL2 (no `SDL_SCANCODE_WEBOS_*`; moonlight uses a
  patched SDL fork). Back may not deliver a KEYUP → decide on KEYDOWN. → memory `webos-rcu-back-key`.
- **GHW HDR**: `videoInfo:null` in `videooutput/getStatus` is a red herring — only the media-server populates
  it; no luna API sets it from an external client. `display/setParam HdrType` is the only HDR knob (public
  perm) and it succeeds. NDL/SMP get HDR from the **bitstream SEI/VUI** (`ndl_load: SetHDRInfo skipped (HDR
  via bitstream SEI)`), which the host now tags. GHW's own `videooutput` bind diverges from webOS's reference
  `demo_script.py`: missing `context` in connect/setVideoData/setDisplayWindow, a `register` that fails
  ("Message status unknown", sent before videooutputd is up, never retried → plane `appId:"unknown"`), and
  `scanType "VIDEO_PROGRESSIVE"` vs the API's `"progressive"`. → task #3, memory `ghw-hdr-setparam`.
- **GHW 2K/4K bottom corruption + choppiness**: GHW's aggressive low-latency tune (`sink sync=FALSE`,
  `qos=FALSE`, render-ASAP, no clean frame-drop) shows **partially-decoded frames** when the VDEC falls
  behind at **144 fps** — intermittent (content-dependent). `touch /tmp/ctm-gst-sync` (sink clock-sync +
  late-drop) fixes it: the sink paces to PTS and drops late frames cleanly. NDL/SMP look clean because the
  media-server does proper flow control. → task #2. **Root cause = 4K@144 overloads the VDEC** (same as the
  SMP 601) → task #4.
- **TV decoder hold**: the HW decoder holds ~1 frame (outputs frame N when N+1 arrives); with the
  event-driven capture (no frame on a static screen) this balloons latency at low fps → the 30fps pacer.
- **GStreamer 1.24** on the TV. `display/setParam` command set: Pattern, HdrType, Freeze, Rgb444,
  AdaptiveStream, WinBlank, WinProperty, VdoConnect, Connect, LatencyPattern, WinRegion, DiagnosticsFB,
  OrbitWindow, OrbitMove — **no colorimetry/HDR-metadata command** beyond HdrType.
- ares CLI for the TV lives at
  `C:\Users\Ciprian\Downloads\beanviser-win64-2.0.7\beanviser\ares-cli\bin` (device `tv`=192.168.0.210,
  `tv55`=.220). `luna-send` is permission-denied from the prisoner shell; end remote cmds with `; echo DONE`
  (ares treats nonzero exit as error); avoid inner single-quotes.
